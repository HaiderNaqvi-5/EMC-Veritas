## 2023-10-13 - Safely Resolving N+1 Queries with Conditional Attributes
**Learning:** When refactoring a loop into bulk fetches to resolve N+1 queries, you must carefully preserve conditional attribute access logic (like `if document_type is DocumentType.ACTIVITY_CERTIFICATE`). Using a blanket comprehension that accesses an attribute on an object that could be `None` (or completely unrelated) in other code paths will introduce dangerous runtime `AttributeError` regressions. Also, when mocking or stubbing complex network or database clients (like Supabase storage), wrapping the client in a simple memoization layer (e.g. `CachedStorage`) is far more maintainable than completely extracting, inlining, and re-implementing their internal logic within your function body.
**Action:** Before converting a loop into a bulk `.in_()` fetch, strictly verify every attribute access path for `None` safety. When implementing in-memory caching to reduce redundant network/database calls within a loop, strongly prefer wrapping the dependency or using `functools.lru_cache` rather than duplicating complex, encapsulated business logic.
