## 2024-10-03 - Starlette CORS Regex Suffix Hijacking Vulnerability
**Vulnerability:** The FastAPI/Starlette backend configured `CORSMiddleware` with `allow_origin_regex` that lacked a terminal anchor (`$`), specifically: `r"https://(?:[a-z0-9-]+\.)?emc-veritas\.pages\.dev"`. Because Starlette uses Python's `re.match` which only enforces matching at the beginning of the string, an attacker could register domains like `emc-veritas.pages.dev.malicious.com` and successfully bypass the CORS policy. Combined with `allow_credentials=True`, this posed a High severity risk for data exfiltration and unauthorized actions.
**Learning:** Starlette's `CORSMiddleware` relies on `re.match` for `allow_origin_regex` evaluation. This means the regex only has to match the *start* of the Origin header. Unanchored regexes in this context are a common misconfiguration leading to CORS bypasses via domain suffix hijacking.
**Prevention:** Always anchor CORS regexes in Starlette/FastAPI with `$` to ensure the entire origin string is strictly validated, preventing attackers from appending malicious domain suffixes.
